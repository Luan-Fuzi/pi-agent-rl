# Badcase 分析：r_hard 为什么低，怎么涨点

日期：2026-09-02 · 对象：R2 @ official_test_200（兼对 R0）· 方法：失分结构分解 + 轨迹级抽查

## 1. r_hard 低的数学结构：不是普遍小失分，是连乘归零

r_hard = r_att × r_option × r_price × r_type，任何子分为 0 则整体归零。R2 的 171 条 done 样本里：

| r_hard 分桶 | 条数 |
|---|---|
| 满分 1.0 | 58 |
| (0.5, 1) | 1 |
| (0, 0.5] | 13 |
| **0** | **99** |

分布几乎是 0/1 二值。**99 条归零样本里 92 条的归零因子是 r_option=0**（R0 同样：96 条归零、93 条栽 r_option）。r_att 的部分失分（65 条 0<x<1）只影响中间分，不是主因。

结论：**r_hard 的涨点问题几乎等价于 r_option 的归零问题。**

## 2. 92 条 r_option=0 的轨迹级分类（R2 @ official_test）

| 类别 | 条数 | 含义 |
|---|---|---|
| B. 买对商品页但选错规格变体 | 17 | purchase_asin==goal_asin，但下单规格与 goal_options 模糊匹配不上 |
| D. 买错商品（同类目） | 69 | 规格自然不可能命中 |
| E. 买错商品（跨类目） | 6 | — |

**关键证据——正确答案大多出现过在模型眼前：**

- B 类 17 条中 **13 条正确规格文本在轨迹中出现过**（页面展示过，没选中）。铁证案例：
  - task 1033：指令"克重不超过2克、价格2040以内"，goal 规格 `8mm绿宝石单个【1.98克】` 就在选项列表里，模型**反复点击 `【2.04克】`**（2.04>2 克、2088>2040 元，双约束都违反）
  - task 1070：指令"蓝色和粉色各一个"，goal `组合粉色1个+蓝色1个`，模型反复点 `蓝色【2个】`
  - task 1192：goal `i carry E 智能磁力版`，模型反复点 `i carry s智能磁力升级版`（型号字母细节选错）
- D 类 69 条中 **52 条正确商品标题在轨迹中出现过**（搜索结果页展示过，没选它）；仅 17 条根本没搜到。

合计 **65/92（71%）是"正确答案在眼前但没选"**，加上 B 类 4 条未确认，真正"搜索失败"的只有约 17~21%。

## 3. 定性结论

r_hard 低的根因**不是搜索能力**（搜得到）、**不是奖励权重**（option_gate 实验证明推不动），而是**候选核对能力**：模型面对高度相似的选项列表时，不会把指令里的约束（数值上限、数量组合、型号细节）逐条比对后再选。这与审计阶段"买错高分大多 r_option=0"的发现同根——当时归因于奖励太松，轨迹证据表明更准确的归因是选择阶段的约束推理失败。

## 4. 涨点路径（按预期收益排序）

量化空间：92 条归零每修好 10 条满分，r_hard 约 +0.05。

1. **选项核对能力（B 类 17 条 + D 类 52 条，空间最大）**
   - 测试时零成本先试：系统提示加入"下单前必须列出指令约束（数值/数量/型号）并与所选规格逐项核对"的固定步骤；或在 buy 前插入自检 turn
   - 训练时：构造"多相似选项 + 数值约束"的针对性 SFT 样本（正确答案演示逐条比对过程）；或把这些任务模式过采样进 RL 训练集（hard case mining）
2. **数值约束的显式推理（B 类典型失败模式）**：克重/价格/数量的上限比较，2B 模型在选项密集时容易漏。SFT 数据里强化"先抽取约束数值，再过滤选项"的范式
3. **搜索改写（仅覆盖 D 类那 17 条没搜到的）**：收益小，优先级最低
4. ~~reward 加权~~：已实验证明无效（R1），不推荐再试

## 5. 深层验尸：错在谁？（2026-09-02 追加）

对 B 类 17 条逐条做了三层核查（轨迹行为、fuzz 匹配复核、goal 合规性），**不全是 2B 模型的错**：

| 归因 | 条数 | 案例 | 证据 |
|---|---|---|---|
| **模型真错**（正确变体可选但选了违反约束的） | ~7 | 1033、1070、337、1192、1271、1105、644 | 1033：指令"≤2克、≤2040元"，goal【1.98克】2039元就在列表里，模型反复点【2.04克】2088元；1070：要"蓝粉各一"，模型点"蓝色2个" |
| **环境判定冤枉**（选的就是 goal 变体，字符串字面不匹配判 0） | ~3 | 509、220、75 | 509：模型点`【 Wireless充电款】…10ml…`vs 库值`【无线充电款】…10ML…`，fuzz=91 仍判 0（映射失败）；220：差"四科"两字 fuzz=94；75：`雪松森林2桶` vs `雪松森林*2桶` 差一个星号 fuzz=62 判 0 |
| **任务数据自相矛盾**（goal 变体本身就超指令预算，怎么选都错） | ~3 | 19（goal 15元>预算10元）、220（316>315）、999（211>200） | 阶段1 冲突审计的 10 倍阈值漏网之鱼（这些是 1.05~1.5 倍轻度冲突） |
| **指令多解**（指令信息不足以唯一锁定变体） | ~4 | 367、72、418、360 | 367：要"提亮肤色"，模型选的选项字面就是"白皙肤色提亮"但 goal 标的是 107 号色 |

D 类抽查 6 条：4 条（704、369、839、680）指令里区分信息充分、模型没去商品页核对规格；1 条（1085）指令多解；1 条（65）需规格层比对。

**SFT 教师数据核查（deepseek-v4-flash，512 条轨迹）**：1323 次中文规格点击中，**76% 没有任何显式思考**，仅 17% 的思考带约束核对关键词，且示例思考多为"确认商品，选择规格并购买"式的动作宣告而非逐条比对。即教师靠自身判断力选对但**不展示核对过程**——2B 学生从 SFT 学到"点一个看着对的规格就 buy"的动作形式，学不到判断力。B/D 类的失败范式是 SFT 数据直接塑造的。

**Thinking 通道核查（2026-09-02 追加，三层全空）**：

| 层 | 状态 | 证据 |
|---|---|---|
| 教师 deepseek-v4-flash | **没开 API reasoning 模式** | 原始轨迹消息无 `reasoning_content` 字段；但 26% turn（1630/6359）自发写了正文形式的思考文本，含高质量逐项核对（"priced at 89 yuan (≤90)…matches all requirements ✓✓✓"） |
| SFT 训练数据 | 思考文本**被模板渲染在 `<think>` 壳外** | qwen3.5 chat template 对 assistant 固定输出空 `<think>\n\n</think>` 壳，教师思考落在壳外正文区；且 74% turn content 为空 |
| 2B 模型（SFT 后 + RL 后） | **think 块 100% 为空** | R2 官方测试轨迹 43,390 个 `<think>` 块无一非空；输出范式 = 空壳 + 直接 tool_call |

含义：模型不是"不愿核对"，而是**思考通道从未被真正启用**——数据里核对行为以错误位置（正文而非 think 区）、少数派（26%）形式存在，被"直接动手"的多数模式淹没。这是 B/D 类失败的最深根因，也指明了修复方向：把思考文本移入 `<think>` 块（数据改写）+ 关键 turn（选规格/buy 前）强制思考覆盖率拉满，重训 SFT；或换 reasoning 模式教师重写关键 turn。

**对涨点路径的修正**：
- 提示词核对验证（零成本）仍然值得做，但预期打折——核对动作不在 SFT 分布里，提示词能不能唤起未知
- 根本解法：SFT 数据注入"显式约束核对"轨迹（教师重写或合成），这直接补上分布缺口
- 评测侧：~6 条冤枉/矛盾案例意味着 r_option 有约 3 个百分点的"假性失分"上限；环境字符串映射缺陷记录在案（不修 ShopSimulator 仓库，作为已知评测噪声处理）

## 6. 建议的下一步实验

最小成本验证：用 R2 checkpoint 加"下单前自检"提示词在 dev_200 上评一次（只改 prompt 模板，~1 小时），看 B 类修复率。若 r_option/r_hard 明显上升，再决定是走 SFT 数据补强还是测试时流程化。
